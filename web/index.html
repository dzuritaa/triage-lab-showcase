Rank 1 is the correct match, and the drafted reply below cites it by number, so retrieval demonstrably fed the answer.

Root cause direction

Check the outbound integration job logs and API/SFTP credentials to the bank; verify whether the transfer attempt failed, and whether authentication or connectivity is the blocker.

Drafted first response

We see the file generated at 20:00 but did not reach the bank. We need to check the transfer job logs immediately to see whether the send attempt failed and why. Can you provide: (1) the exact filename and size of the file in the outbound folder, (2) whether your bank credential or API key for this payment file transfer has been rotated or renewed recently, and (3) access to the integration job logs covering 20:00–21:30 last night. If the transfer failed due to credential expiry or rotation (similar to INC-1003), we may need to refresh those with the bank and retry.

1,254 input + 263 output tokens · $0.0026 per ticket · about 1,900 tickets per $5 of credit.

How it was measured

Ten held-out tickets the system has never seen, written so they share no phrasing with the corpus they are scored against. Every number on this page comes out of one command, and the same command runs in CI on every pull request — including pull requests from forks, because nothing in the evaluation path needs a secret or a network.

Regression floors sit about ten points below measured performance, so ordinary variation does not break the build but a real drop does. An earlier floor was set at 70% before anything had been measured, above what the system had ever achieved, which would have left the build permanently red. A floor above demonstrated performance is an aspiration, and aspirations belong in a decision record, not in an assertion.

The case it gets wrong

Recall@3 of 90% flatters the retriever. The honest reading is in the failure, so here it is.

CASE EVAL‑02 Retrieval failed · correction filed

A contractor cannot open the finance application

The audit starts at 9am tomorrow and he has three days on site. The right documents are about security group membership. The retriever returned branch-office network slowness, an unrelated login loop, and the change freeze calendar.

What the reporter wrote “cannot open the finance application”
What the answer says “the logon script maps only the drives the account already has rights to”

Same problem, two vocabularies, almost no shared words. A lexical matcher cannot cross that gap by construction; no amount of tuning fixes it. This single case is the clearest argument for adding embeddings, and it is why the next phase measures them rather than assuming them.

Worth noting what happened anyway: handed three irrelevant documents, the model still returned the correct category and priority, and pointed at group membership, the content of the article it was never shown. The system degraded gracefully. It also means recall@3 overstates how much retrieval is currently contributing.

Why there is no vector database

Twenty-five documents. BM25 in about 150 lines of standard-library Python beats random retrieval four-fold, needs no second vendor, no second API key, no index to keep warm, and no monthly bill. The retrieval path is readable in one sitting and testable with no network at all.

That is a decision with a stated expiry: it reverses if the corpus passes roughly 5,000 documents, if recall@1 starts mattering more than recall@3, or if an embedding adapter beats these numbers by enough to justify the cost. All of it is written down: the evidence, the case against, and the conditions that would change it.
